Endpoints REST

Todos os endpoints são expostos por CapGiroController sob o prefixo /cap-giro. As respostas usam JSON.

Base & convenções

Base path/cap-giro
Porta padrão8081 (variável SERVER_PORT)
Content-Typeapplication/json
CorrelaçãoOpcional via correlationId no corpo de início; gerado automaticamente se ausente.

Iniciar orquestração

POST /cap-giro

Cria e dispara uma orquestração de cap-giro de forma assíncrona. Não aguarda a conclusão das etapas.

Request body opcional

{
  "correlationId": "a1b2c3d4-..."   // opcional; se ausente, gera um UUID
}

O corpo inteiro é opcional. Enviar POST /cap-giro sem body é válido.

Respostas

CódigoDescriçãoBody
202 Accepted Orquestração aceita para processamento. IniciarOrquestracaoResponse 
{
  "orquestracaoId": "665f1c2a9b4e2a0012a3b4c5"
}

Exemplo

curl -i -X POST http://localhost:8081/cap-giro \
  -H "Content-Type: application/json" \
  -d '{ "correlationId": "pedido-42" }'

Consultar o crédito de negócio

GET /cap-giro/{orquestracaoId}/credito

Retorna o crédito de negócio (cap-giro) associado à orquestração e seu historico. O crédito compartilha o id com a orquestração e é atualizado a cada avanço de etapa (append de uma nova entrada no histórico).

Aprovar (retomar) uma etapa

POST /cap-giro/{orquestracaoId}/etapas/{etapa}/aprovar

Retoma uma etapa suspensa em PENDENTE_DE_INTERACAO. Não executa a etapa de forma síncrona: registra a interação (tipo + aprovadoEm), transiciona a etapa para PENDENTE e republica a mensagem na fila para retomada assíncrona. É idempotente.

Parâmetros de path

NomeTipoDescrição
orquestracaoIdstringId da orquestração.
etapastringNome canônico da etapa (ex.: baas:etapa:cap-giro:elegibilidade).

Request body opcional

{
  "tipo": "HUMANA",                 // opcional; HUMANA ou MAQUINA; assume HUMANA se ausente
  "dados": {                        // opcional; dados de negocio da retomada
    "idSimulacao": "1a7c9d20-55b3-4a11-9c6f-4d0e8b2f7a44"
  },
  "correlationId": "a1b2c3d4-..."   // opcional; se ausente, gera um UUID
}

O corpo inteiro é opcional. Enviar a requisição sem body assume tipo = HUMANA. Quando a etapa seguinte depende de uma escolha do cliente (ex.: a etapa de simulação, em que o cliente informa qual simulação aceitar), esses dados vão em dados — são persistidos na interação e repassados ao processor no reprocessamento.

Respostas

CódigoDescriçãoBody
202 AcceptedAprovação registrada; etapa republicada para retomada.AprovarEtapaResponse
200 OKAprovação já processada anteriormente (idempotente).AprovarEtapaResponse
404 Not FoundOrquestração ou etapa não encontrada.—
 
{
  "orquestracaoId": "665f1c2a9b4e2a0012a3b4c5",
  "etapa": "baas:etapa:cap-giro:elegibilidade",
  "resultado": "APROVADA"
}

Exemplo

curl -i -X POST \
  http://localhost:8081/cap-giro/665f1c2a9b4e2a0012a3b4c5/etapas/baas:etapa:cap-giro:elegibilidade/aprovar \
  -H "Content-Type: application/json" \
  -d '{ "tipo": "HUMANA" }'

Modelos de dados

OrquestracaoResponse

orquestracaoIdstringId da orquestração.
namestringNome da orquestração.

statusstringPENDENTE, EM_EXECUCAO, CONCLUIDA, ERRO.
dataCriacaoInstantData de criação.
dataAtualizacaoInstantÚltima atualização.
etapasEtapaResponseView[]Etapas da orquestração.

EtapaResponseView

CampoTipoDescrição
namestringNome canônico da etapa.
orderintOrdem da etapa.
statusstringAGUARDANDO, PENDENTE, EM_EXECUCAO, PENDENTE_DE_INTERACAO, CONCLUIDA, ERRO.

AprovarEtapaRequest opcional

CampoTipoDescrição
tipostringOrigem da interação: HUMANA ou MAQUINA (assume HUMANA se ausente).

correlationIdstringCorrelação opcional; gerado se ausente.

CampoTipoDescrição

etapastringNome canônico da etapa aprovada.
resultadostringAPROVADA, JA_PROCESSADA ou NAO_ENCONTRADA.

CreditoResponse

CampoTipoDescrição

HistoricoView

CampoTipoDescrição

descricaostringDescrição de negócio da situação.
dataHoraCriacaoInstantMomento de criação da entrada.
dataHoraAtualizacaoInstantMomento da última atualização da entrada.

IniciarOrquestracaoResponse

CampoTipoDescrição
